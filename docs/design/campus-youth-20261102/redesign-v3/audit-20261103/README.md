## 验证结果

- `node --test tests/*.test.cjs`：140项通过、0失败，含本轮8项走查回归测试及1项重新选图回归测试。详见[最新测试日志](tests-140.log)。覆盖规格回传、工具上下文、重复导航、无效路径/尺寸、导出格式保护、主题可见性及本地图标。
- 自有39份 JS 语法检查、30份 JSON 解析检查通过；34个静态图标名没有缺失字形；`git diff --check` 通过。
- 上一轮已走通“二寸→选图→蓝底→取消/失败展示→重试→导出→格式选择→模拟相册保存”的原生模拟流程；其中处理/失败展示部分使用临时页面数据，不能等同真实网络故障测试。
- 本轮在 `/private/tmp` 独立副本中替换启动与请求模块，仅使用本地样片、内存草稿及模拟相册保存。已确认副本 `baseUrl` 为 `https://local-qa.invalid`；随后官方自动化反复返回 `Remote debug connection lost`，部分运行时信息与显示状态不一致，原生点击也未得到可信反馈，故未将这轮完整交互重测计为通过。没有为了继续测试重启用户正在操作的原项目。

## 服务器地址与联调

应用统一入口已切换为 `https://www.myhaibin.top/new-api`。2026-11-03再次只读验证 `/api/app/config`：HTTP 200、`application/json`、业务 code 200。原计划 `/shiguang-api` 当前返回管理端 HTML，暂不用于测试。README 与路由回归测试已同步。

原项目中的 request、uploadFile、chooseMedia、saveImageToPhotosAlbum 测试 mock 已撤销，并已重新编译，用户可以手动测试换底色。该配置接口验证只证明地址和配置返回正常，不证明真实人像处理、背景合成或相册权限已联调。

真实样片上传验证被自动审批拒绝，原因为含人脸照片的外部传输未获明确授权；该请求未执行。真实换底色效果需要用户使用自己的照片测试，本轮不声称已经验证成功。

本轮没有发布小程序或部署后端；保留工作区原有业务改动。隔离测试代码仅存在临时目录，不进入应用源码。

## 上传后仍显示样片的补充修复

用户反馈重新选图后仍显示测试照片。检查时，原项目未发现 QA 启动代码或测试草稿；配置接口返回真实服务器字段。再次显式撤销 request、uploadFile、chooseMedia 与 saveImageToPhotosAlbum 的运行时 mock，并关闭重开原项目。未据此断言用户此前看到的现象必然由 mock 引起。

复现并修复了另一处直接相关缺陷：`processTransparentImage` 开始时只清理了 resultPath，未清理 previewPath，重新选图或裁剪后，如果新照片处理失败，WXML 会优先显示旧照片的预览。现在每次重新处理同步撤下旧预览，处理和失败状态都显示当前选中的原图；同时检查选图返回是否含有效路径。

新增回归测试先在旧代码上复现失败，再验证新图上传中及失败后都不恢复旧预览。全量测试现为140项通过、0失败；此前139项日志保留为上一轮记录。未为本次修复上传任何用户照片。

重开后的缺失文件上传探针遇到官方自动化响应超时，没有得到可信返回，不能将该探针记为通过；修复验证以回归测试与已成功返回的 restore 操作为依据。

用户确认是在手机预览／真机调试中遇到问题。已使用原项目生成新的手机预览二维码（编译包1,340,529字节），未发布正式版；新包使用 `/new-api` 且不包含隔离 QA 启动或模块替换代码。手机实际选图及服务端处理结果仍待用户扫码复测。
