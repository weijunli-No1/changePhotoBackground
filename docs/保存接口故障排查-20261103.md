# 手机保存接口故障排查

2026-11-03，用户确认新手机预览已显示自己选择的照片，但点击保存出现“服务暂不可用”。

## 已确认

- 小程序的电子照片保存先调用 `/new-api/api/history/save`，成功后才写入手机相册。该提示来自请求响应校验；不是相册权限拒绝提示。
- 只读查看 Nginx 日志：22:37:21、22:38:31、22:38:35、22:39:10 的保存请求均返回 HTTP 500。22:38:17 的 `/new-api/api/photo/generate-layout` 返回 HTTP 200。登录请求返回 HTTP 200。
- 对保存接口发送不含照片、不含有效身份的诊断 JSON，84字节及1,500,084字节请求均返回 HTTP 200、业务 code 401、“用户未登录”。说明保存路由及 JSON 请求格式可达；没有证明更大请求体均可接受。
- Nginx 照片路由使用 `new_backend`，实际转发至 `1ln0498ig7766.vicp.fun:58079`。照片 Java 服务不在已连接的云服务器，也未在当前 Mac 上发现对应 Java 进程。
- 云服务器上的 MinIO 健康检查返回 HTTP 200，公开证书有效期为2026-11-02至2027-01-30。健康检查不能证明照片后端具有有效写入凭据或正确的桶配置。

## 根因尚待定位

单张云保存比排版多出 MinIO 上传及历史记录写入链路。存储写入、历史表写入等均可能导致 HTTP 500；没有应用异常堆栈前，不将其认定为某一种原因。

已向用户询问隧道后机器的运行位置/连接方式，或 `logs/photo-bg-error.log` 中保存时间附近的异常（尤其 `Caused by`）。拿到后继续修复并验证。当前没有修改生产配置、部署应用、绕过保存次数或跳过云端校验，也没有重新上传用户照片。

相关本地代码：`mini-program/pages/export/export.js`、`mini-program/utils/api.js`、`backend/src/main/java/com/photo/bg/controller/PhotoHistoryController.java`、`backend/src/main/java/com/photo/bg/service/impl/MinioStorageServiceImpl.java`。
