## Nginx 与发布

合并示例：`backend/deploy/nginx-shiguang.conf.example`。示例仅使用一个 `/shiguang-api/` location，同时承载所有业务及微信 GET/POST 回调。

1. 核实照片后端的实际监听地址。示例的 `127.0.0.1:8080` 仅对应项目默认配置，不能误指向其他项目。
2. 在 `www.myhaibin.top` 现有 HTTPS server 块加入这一个 location。`proxy_pass` 的结尾 `/` 用于剥离 `/shiguang-api/`，必须保留；例如回调公网路径 `/shiguang-api/wechat/member/push` 会转发为 Java 内部路径 `/wechat/member/push`。原被占用前缀不属于这次配置的路由范围。
3. 业务上传限制为 50 MB，转发保留 Authorization、请求方法和正文；图片处理读写超时留出 130 秒。
4. 部署后端之前执行会员数据库迁移并加载服务器私有配置，处理既有已发布客户端的会话认证兼容问题（详见会员方案）。先保持会员购买关闭。
5. 使用服务器上的 `nginx -t` 检查合并后的完整配置，通过后再 reload。确认新入口 `/api/app/config` 返回本项目正常 JSON，而不是 HTML、其他项目响应或重定向。
6. 验证登录、抠图、换底色、水印、作品、额度、会员、微信签名握手与加密通知，再发布使用新 baseUrl 的小程序。鉴于原前缀被其他业务占用，不把新请求重定向回旧前缀。
7. 小程序 request/uploadFile 合法域名继续使用 `https://www.myhaibin.top`；downloadFile 合法域名还需覆盖实际图片存储域名。改变 URL 路径不替代原有合法域名设置。
