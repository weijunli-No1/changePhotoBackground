## 今后迭代使用的设计约定

1. 每个页面围绕一个主要任务组织内容；照片处理页的主按钮始终对应下一步或保存。
2. 本地工具先用后登录；证件照保存和云端作品才进入登录流程，不用广告或资料填写打断编辑。
3. 等待发生在哪里，就在哪里显示状态；能说明阶段时展示实际阶段，不编造进度百分比。
4. 每个失败状态同时具备原因和有效下一步。原图丢失应该重新选择，网络失败才适合重试。
5. 错误提示持续可见，表单标明出错字段；成功可以使用轻提示，关键错误不能只闪现一下。
6. 选中状态有边框、图标或文字等辅助表达；主要交互有读屏名称、角色及必要状态。
7. 关键小控件按至少44px触控高度／宽度检查，图片和文字指向同一动作时尽量合并热区。
8. 使用一致的导航、底部主操作和恢复入口；每次修改都复查小屏、键盘、深浅主题与真实系统能力。

## 本轮发现并修复的问题

P1：可能让用户得到错误作品或中断核心任务，优先修复。P2：明显增加操作成本、等待焦虑或恢复困难。P3：文案或细节改进。

| 编号 / 优先级 | 原来的体验问题与复现方式 | 规范依据 | 已完成的处理与验证 |
| --- | --- | --- | --- |
| UX-01 / P1 | 工具页已有结果后，重新选图读取失败，仍可能导出旧结果；读取期间改参数还可能触发对旧原图的处理 | 2.3 异常恢复、3.2 防误操作 | 开始读取就清空旧输出并进入处理中，失败清空不可用原图、禁止导出；单元测试和原生失效图片场景验证 |
| UX-02 / P2 | 本地处理失败只显示报错，缺少直接重试入口，用户需要重新选照片 | 2.3 异常恢复 | 增加“重试处理”；文件失效时入口改为“重新选择照片”；原生执行重试后恢复可导出状态 |
| UX-03 / P2 | 证件照草稿被清理或原图丢失，错误行统一显示“点击重试”，实际重试没有有效来源 | 2.3 异常恢复 | 明确分为重选和重试；失效草稿显示常驻说明与重选入口，无原图时隐藏无效对比操作 |
| UX-04 / P2 | 换底色失败后的重试重新执行抠图，带来额外上传与等待 | 2.2 减少等待、3.3 性能 | 保留已成功的照片，记录失败目标色，仅重试换色接口；测试确认不会再次调用抠图 |
| UX-05 / P2 | 制作证件照可能等待较长时间，照片区域没有直接取消入口 | 2.2 等待反馈与取消 | 增加“取消处理”，终止当前客户端原生请求、清理定时器并隔离迟到结果；实际点击及迟到回调测试通过。取消客户端等待不等于服务器算法立即停止执行 |
| UX-06 / P2 | 自定义宽高错误只有短暂 Toast，用户不容易判断哪个字段有问题 | 2.3 表单错误 | 改为常驻错误文案，错误输入框描边和 aria-invalid，自动滚动到输入区；修正后可继续，原生截图确认 |
| UX-07 / P2 | 云端删除、比例选项、规格关闭等部分控件的热区偏小；小屏下单用 rpx 会进一步缩小 | 3.2、适老化热区指引 | 扩大删除、比例、常用压缩选项、规格输入／关闭和主要操作热区，采用44px最低检查值；需要真机继续检查相邻控件误触 |
| UX-08 / P2 | 保存始终只显示“正在保存”，不能区分登录、排版、云端或相册阶段；工具等待仅有静态文字 | 2.2 及时反馈 | 增加对应实际流程的阶段文案和单个局部动画，不显示虚假进度；原生检查保存按钮文字及布局 |
| UX-09 / P2 | 多数自绘操作只有 view 点击，角色及状态不完整；对比原图仅支持按住 | 无障碍指南、统一交互 | 补充主要按钮、选项、禁用状态与输入名称；原图改为点击切换，原生连续点击验证；系统读屏未验收 |
| UX-10 / P2 | 云端作品的登录入口没有等待状态，可连续触发确认 | 2.2、3.2 | 增加登录等待反馈和重复触发保护；取消后恢复可用，测试通过 |
| UX-11 / P2 | 用户开始制作证件照前，没有就近说明照片将进行云端处理 | 1.2 流程、知情与可控 | 首页规格面板在选图前展示照片建议及上传用途；本地图像工具继续显示本机处理说明 |
| UX-12 / P3 | 压缩入口写“保留清晰”，容易被理解为压缩不损失画质 | 清晰表达 | 改为“调整体积与清晰度”；保留 JPEG 和实际结果大小说明 |

## 仍未关闭的事项

这些不是“已通过”，也不应因单元测试成功就忽略。

| 编号 / 优先级 | 差距或待验收项 | 后续验收要求 |
| --- | --- | --- |
| R-01 / P2 | 自定义页面尚未完整跟随微信大字号设置；固定 rpx 字号不等于适老化完成 | 按官方 fontSizeScaleFactor 设计文字、容器和折行；覆盖小屏、大字号下的编辑器面板、规格输入、资料键盘和底部按钮。不能只全局放大文字后宣布完成 |
| R-02 / P2 | 已补充 ARIA，但 iOS VoiceOver / Android TalkBack 的焦点顺序、弹层隔离、朗读与激活尚未实测 | 在两类手机实际完成选择规格、编辑、失败重试、保存和退出；需检查动态错误能否被及时感知 |
| R-03 / 真机验收 | 广告库存、微信登录、相册授权恢复、客服接待、系统深浅主题切换以及页面真实滚动 | 使用体验账号，在 iOS / Android 分别验证；模拟器回调替身不能证明平台服务已配置成功 |

## 验证证据与边界

- 全量61项自动化测试通过，本轮新增8项，涵盖取消及迟到结果、错误重试、失效图片、表单定位与登录防重。
- 第一方 JS 语法、JSON 解析与12份 WXML 编译通过。所有9个路由继续使用 Skyline + glass-easel。
- 官方 miniprogram-automator 逐页检查9个路由；使用项目生成式演示照片和临时账号，不使用真实用户照片，不提交云端保存、不制造广告观看、不发送客服消息。结束后恢复账号和会话，删除测试图片。
- 截图中的处理中、保存阶段等部分状态通过模拟回调／页面状态触发，用于检查布局；取消、原图切换、规格错误与本地重试执行实际页面操作。不能据此宣称真实云端耗时或手机相册已经验收。
- 主要截图位于 `design/official-ux/`：`home.png`、`spec-guide.png`、`spec-error.png`、`editor-missing.png`、`editor-processing.png`、`editor-cancelled.png`、`tools-missing.png`、`tools-retry.png`、`export.png`、`export-saving.png`、`history-login.png`、`profile.png`、`account.png`、`support.png`、`privacy.png`。
- 基础颜色按相对亮度公式测算：浅色正文／白底16.34:1、辅助文字／白底5.51:1、浅色按钮9.49:1；深色正文16.76:1、辅助文字8.19:1、深色按钮8.45:1。它们高于本次普通文字4.5:1检查目标，但不代表所有照片叠加层、半透明态与禁用态均已逐像素验证。
- 本轮没有修改后端照片处理、保存计次和广告奖励业务接口；新增的原生任务引用仅用于中断客户端等待和丢弃取消后的结果。
