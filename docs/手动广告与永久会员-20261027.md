## 官方资料核对

直接读取微信官方页面（浏览器检索抓取失败后，通过 HTTPS 下载官方 HTML 核对正文）：

- [激励视频](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/ad/rewarded-video-ad.html)：实例仅限当前页面使用；用户主动触发 show；只有关闭回调 isEnded=true 才给奖励。退出页面解除监听。
- [个人主体虚拟支付](https://developers.weixin.qq.com/miniprogram/dev/platform-capabilities/business-capabilities/virtual-payment/person)：道具直购 short_series_goods；签名和 session_key 留在服务端；正式环境 env=0；通知发货和查单兜底，前端 success 不授予权益。按已开通工具类目个人主体能力实现，正式启用前应复核认证备案与商品发布情况。官方当前个人主体全终端月支付限额为 10 万元；Android 等费率 1%，iOS 12%；Android 等结算 T+3，iOS 约 45–60 天。Android 等可通过后台退款，iOS 经 Apple 申请，平台确认后收回对应订单权益。
- [客户端虚拟支付](https://developers.weixin.qq.com/miniprogram/dev/api/payment/wx.requestVirtualPayment.html)：两套 HMAC-SHA256 签名；金额按分；订单号每次新建、不复用。iOS 须先开通 IAP、配置小程序简称，客户端不低于 8.0.68。
- [查询订单](https://developers.weixin.qq.com/miniprogram/dev/server/API/VirtualPayment/api_query_order)：请求 order_id；状态 2 已支付待发货、3 发货中、4 已发货。状态 5 为退款商户侧扣款完成，8 为退款用户侧收款完成；本实现任一确认即收回对应订单权益。请求 env=0，而返回 env_type=1 代表现网，不能混用。
- [补发货确认](https://developers.weixin.qq.com/miniprogram/dev/server/API/VirtualPayment/api_notify_provide_goods.html)：通知回调成功不需另调，主动查单补发后调用该接口。
- [上传道具](https://developers.weixin.qq.com/miniprogram/dev/server/API/VirtualPayment/api_start_upload_goods.html)：道具 ID 和名称最长 20 字符；ID 使用字母、数字、下划线、连字符；图片支持 JPG、PNG。公开接口未写固定像素尺寸，本文的 512 方图是设计交付尺寸，不冒充官方强制规格。控制台若另有限制，以实际表单为准。

## 广告位置与规则

| 页面/场景 | 类型 | 触发与布局 |
| --- | --- | --- |
| 首页 | 原生模板广告 | 全部主要内容之后、继续编辑区域下方；一个广告位，不自动刷新 |
| 全部工具 | 原生模板广告 | 工具列表底部，独立组件，不混入搜索结果按钮 |
| 证件照、考试照及排版保存 | 激励视频 | 免费额度耗尽后，弹出明确说明，用户点击“看视频，继续保存”才播放；完整观看增加一次保存机会 |
| 编辑、规格选择、裁剪、水印、作品管理、我的、会员页 | 无展示广告 | 保障制作、管理与购买流程；本地工具沿用免费直接保存 |

暂不接入插屏、开屏、强制视频。原有每日免费 5 次、每完整观看一条视频增加 1 次、当日看满 5 次可当日不限次数的规则保留；当日不限次数不等于永久会员，仍可能看到展示广告。

### 首帧免广告保障

1. 会员状态仅使用内存，不从本地缓存推断“不是会员”。默认状态 unknown，adFree=true。
2. 冷启动/回前台先让权益失效；广告组件默认 allowed=false，其 WXML 不创建 ad-custom。
3. 静默微信登录获得服务端会话后查询权益；只有服务端明确返回有效非会员状态，且广告位已配置，才挂载广告。
4. 页面返回再次预检；组件页面 hide 时关闭挂载，重新进入不使用旧非会员状态抢先请求广告。
5. 接口超时、401、旧服务缺失会员字段均保持无广告，不用延时移除或透明遮盖掩饰广告。
6. 激励视频在弹出确认前、用户确认后播放前分别刷新会员。永久会员直接继续保存，不取广告位、不调用广告 SDK。
7. 发起购买前持久化业务单号并同步使全局广告权限失效。支付结果待确认时，首页和工具页也抑制广告；本地订单记录仅用于服务端查单，不能开通会员。
8. 退出/切换身份会使旧请求失效。会员页首屏使用“正在确认权益”，个人页与导出页也不先显示普通用户促销和视频文案。

页面本身可以先展示工具内容；广告创建严格在权益预检之后，不阻塞整个工具页面。会员不会经历“先看到广告，再异步消失”。

## 服务端闭环与接口

下表为 Java 内部路由；公网统一加 `/shiguang-api` 前缀，包含微信回调。

新增表 `t_member_session`、`t_member_order`；不修改既有用户表或每日统计字段。会话令牌随机生成 32 字节，数据库仅存 SHA-256 哈希、2 小时有效；不将 session_key 保存到数据库或返回前端。

| 接口 | 说明 |
| --- | --- |
| POST /api/user/login | 原登录响应新增 sessionToken；前端只在内存保存令牌 |
| GET /api/member/status | Bearer 会话认证；返回会员、免广告、无限保存、价格及购买能力 |
| POST /api/member/orders | Bearer 认证 + 新 wx.login code；服务端换 session_key，校验是同一微信账号后生成唯一订单和签名 |
| GET /api/member/orders/{id} | 仅可查询自己订单；服务端调用微信查单、处理发货/退款后返回权益 |
| GET /wechat/member/push | 消息推送 URL 的验证握手 |
| POST /wechat/member/push | **XML + 安全模式**；SDK 验证密文签名、AES 解密及 AppID，XML 禁止外部实体；再次查微信订单核实后处理通知 |

下单价格、商品 ID、数量全部由服务端固定。平台查单必须匹配本地 order_id、金额、透传 attach、现网环境和支付订单类型。以 wx_order_id 唯一索引、事务和订单行锁实现幂等。订单 ACTIVE 授予永久会员；REFUNDED 后迟到的付款/发货通知不能恢复会员。同一用户如有其他有效订单，仍保留其对应权益。

每 5 分钟执行补单任务，分批轮询最多 50 笔 PENDING/ACTIVE 订单，失败逐笔记录、下轮重试；已激活订单也轮询退款兜底。补发货先原子保存权益，随后通知微信，超时可重试。用户异常退出后可通过本地未确认单号恢复；换设备则通过回调、后台补单与同微信账号查询权益恢复。

普通配额与会员保存最终仍由 Java 服务判断，单图保存与六寸排版均生效。usage、recordAd、history/save、generate-layout 增加会话及账号归属校验，不能只伪造会员 openid 绕过配额。

激励视频奖励仍基于现有微信客户端 isEnded 回调并请求服务器记录；这不是平台服务端广告结算回调或完整广告反作弊方案。会员交易本身不依赖该奖励记录。

日志切面省略登录/会员接口的参数与响应，避免令牌、签名和消息正文进入业务日志。
