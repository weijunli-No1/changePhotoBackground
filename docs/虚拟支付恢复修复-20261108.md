# 虚拟支付恢复修复 · 2026-11-08

- 用户锁内检查 PENDING / REVIEW 订单；有旧订单只返回恢复单号，不返回新的支付签名。已开通会员仍禁止重复下单。
- 会员状态接口返回服务端待确认单号，用于换设备、清缓存后的恢复。
- 累计 12 次核验或待支付超过 24 小时，转 REVIEW 暂停自动查单；时间流逝、客户端取消和网络异常均不是未付款证明，不自动关闭或开放重复付款。
- REVIEW 仍可由用户手动查询或真实付款回调恢复。最终 CLOSED / REFUNDED 返回终态，客户端清除待确认记录。
- ACTIVE 订单核验成功后下一次自动核验在一天后；连续核验失败 12 次暂停自动查询，保留已有会员权益，回调和手动核验仍可恢复。
- iOS 退款问询使用安全模式加密回复，返回 IosRefundQueryResponse。当前无足够权益使用凭据拒绝退款，因此建议退款（result_code=0）；这不是执行退款，最终权益回收仍依赖平台结果核验。
- 问询的审计记录异步写入，回复不等待数据库或微信 API；队列有容量上限，记录失败仅输出不含密钥的告警。
- 原有金额、订单号、环境和订单类型匹配校验保持不变；本轮不定位此前“平台订单信息不匹配”。

部署前执行可重复的增量脚本 database/migrations/20261108_membership_recovery.sql。后端须先部署，前端需重新预览/发布以使用跨设备恢复和新状态提示。

验证范围：Java 单元测试、完整前端回归测试，以及本机 MySQL 的会话级临时表集成验证。没有执行真实付款或退款，未修改真实订单状态。
